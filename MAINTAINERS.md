## How to reach us

- **Questions and ideas:** [GitHub Discussions](https://github.com/The-Burnes-Center/abe/discussions).
- **Bugs and planned work:** open an issue with the template. To get a maintainer's attention on an existing issue or pull request, mention them by handle (for example `@DB-25`).
- **Security vulnerabilities:** use [private vulnerability reporting](https://github.com/The-Burnes-Center/abe/security/advisories/new). Do not open a public issue. See [SECURITY.md](SECURITY.md).
- **Code of Conduct concerns:** report them privately to the maintainers listed above, by GitHub handle. The easiest route is the same private advisory form as security reports: say in the first line that it is a Code of Conduct matter. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). If the concern is about a maintainer, address it to another maintainer when there is one, and otherwise to AI for Impact through the repository's organization page.

There are no email addresses for the project on purpose. Everything goes through GitHub so reports stay attached to the repository.

Maintainers are busy with other work. Replies are best effort (see [SUPPORT.md](SUPPORT.md)).

## Becoming a maintainer

Maintainers are chosen from contributors who have shown steady, careful work on the project. A typical path:

1. Contribute over a few months: merged pull requests, helpful reviews, and answers to questions in Discussions.
2. Show you understand the parts of the system you would own (infrastructure, chat Lambdas, frontend, docs) and the project's security model.
3. A current maintainer nominates you in a Discussion or privately by GitHub handle. If there is no objection from the other maintainers within 7 days, you are added.

New maintainers get write access, a row in this table and an entry in `.github/CODEOWNERS`. Maintainers who step back are moved to an "Emeritus" list here, with thanks, and lose write access.
